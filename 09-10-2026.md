# GeckoJam

```
1. Playfield Geometry & Routing

PlayfieldGeometry.cs — [NEW]
- Defined the corridor ring, neck and target hole in cell space as the single source that routing, camera framing and the wall all read from
- Added Margins (per-side corridor width) replacing the fixed CorridorCells constant; the ring is the boundary of x in [-Left, W-1+Right], y in [-Down, H-1+Up]
- Hole column fixed to the centre of the board, so lopsided side margins do not drag it off centre
- Hole row derived from the bottom margin alone — centre of the bottom padding, -(Down+1)/2 floored toward the board; removed targetHoleRowOffset as an input
- Removed the neck and its outline branch: the hole always lands inside the corridor band, so they were unreachable
- PlayfieldExtents reports all four sides separately; dropped a stray half-cell from the bottom edge
- Added the content frame (grid + hole, no corridor, no padding) used by large-grid camera framing

ArrowPictureService.cs — [NEW]
- Added BuildExitRoute: straight out of the grid until the route reaches the ring, around the ring the cheaper way, then down the neck one cell at a time, with a guard against a runaway loop
- Per-cell waypoints down the neck, because UpdateLinePoints lays body vertices on exactly those marks and one long segment smears the tiled pattern
- Added TargetHoleWorldPosition — one shared hole per level instead of one per arrow
- Added bottomLaneFollowsHole handling: lane hugs the wall by default, or moves onto the hole row so geckos walk in without turning
- A gecko exiting downward on the hole's own column now drops straight in instead of walking past the hole, down to the wall, sideways and back up
- Added the wall fade call on win

Arrow.cs / Arrow.Func.cs / Arrow.Visual.cs — [MOD]
- Stored the exit route in _exitCells/_exitPoints/_exitDistances, kept apart from _waypoints, which stays the public "body on the board" API that Ice and KeyLock build their visuals from
- Position and direction sampling now follow the corridor polyline instead of extrapolating a straight ray, so the body bends through corners on its own
- Left _committed, Waiting, TriggerReversal and IsHeadBlockedByStationary untouched; geckos may overlap off the board and still block each other on it

MapSpawner.cs — [MOD]
- Spawns one shared hole per level instead of one hole per arrow
- HideHoles now also fades the wall out (winWallFadeDuration), fired from OnAllArrowsCleared in parallel with the camera reset
- CelebrateThenWinAsync waits out whatever is left of the fade before the picture reveal, because AnimateToResting returns immediately when the player never zoomed or panned

WallView.cs — [NEW]
- Built the decorative border as one rounded mesh band instead of tiled pieces, which cornered in visible steps; one draw call
- UVs run along the band so tiled art stays undistorted at any board size
- Added a fade driven by vertex-colour alpha rather than the material, so a shared art material is not written into by every wall using it

HoleView.cs — [MOD]
- Split Dismiss into PlayImpact (pop-out plus puff tinted to the gecko that just dived, then back to rest); retiring moved to HideHoles on win
- Added _diveCount and EndDive so the dive pulse is reference-counted and runs while any gecko is still going in
- Replaced dismissLinger and the pending _dismissTween self-return to the pool
- Reads _visualBaseScale in Awake so the dive pulse and pop-out stay proportional when the sprite scale changes

Hole.prefab — [MOD]
- Visual child scale 0.5 -> 1

3. Camera

CameraScaleHandler.cs — [MOD]
- Frames the whole playfield, taking each half-extent from the further side, since the playfield is asymmetric both vertically (neck and hole hang below the grid) and horizontally (per-side margins)
- Grids whose longest side reaches contentFramingMinGridCells rest on a frame hugging the grid plus the hole, dropping the corridor and both paddings; the pinch range is untouched
- ResolveHomePosition lowers the camera by ContentCenterOffsetY so the hole stays in frame, clamped to the pan range, with _authoredPos keeping the scene's original camera position so a reload does not stack the offset

CameraZoomHandler.cs — [MOD]
- Added RestingSize as the single source of the resting frame; the appear animation rested at MinSize while ResolveInitialSize returned ComfortSize, so AnimateToHome ended on a different framing than the level start
- AnimateToResting (the win-time camera reset) now calls RestingSize instead of duplicating the appear animation's expression

- Added wallEnabled
- Added bottomLaneFollowsHole
```
