# gecko-jam

```
1. Arrow Core / Grid State

ArrowPictureService.cs — [MOD]
- Added CellState enum (Empty / Idle / Exiting / Waiting / Backing / Blocked); only Idle and Blocked count as stationary blockers
- Replaced the three parallel grids (_occupied, _arrowGrid, _staticBlocked) with one Cell[,] holding State + owning Arrow
- Added TryClaimCell(cell, arrow, state): claims only an Empty cell, returns false when another arrow or board element holds it
- Added ForceSetCell() for the resting footprint at spawn and re-occupying cells while reversing home
- Added SetCellState() which changes a cell only if the passed arrow still owns it
- Added ReleaseCell() which frees a cell only if the passed arrow owns it
- Added GetCellState() accessor
- SetStaticBlocked() now claims only Empty cells so a board element cannot overwrite an arrow footprint
- Merged TryGetBlockerDistance and TryGetStationaryBlockerDistance into one ScanBlocker() with a stationaryOnly flag and an ignore-arrow parameter
- Removed IsCellClearingArrow(); moving arrows are now identified by cell state instead of Arrow.IsMoving
- Made DirectionToStep() public so Arrow can cache the exit step

Arrow.Func.cs — [MOD]
- Split AnimateMovement into AnimateForward() and AnimateReversing()
- AnimateForward claims each cell ahead before the visual head enters it and stops at the cell boundary when the claim fails
- On a failed claim, reverses when the blocker is Idle/Blocked and waits when it belongs to a moving arrow
- AnimateReversing claim-gates the leading tail the same way so a backing arrow holds instead of overwriting another arrow
- Added AdvanceBoth() moving head and tail together so body length stays constant
- Added SeqCell() and SeqCenterDist() describing the swept cell sequence (path cells then exit-lane cells)
- Added ClaimPathCellsIdle() replacing SyncGridOccupancyFromPath()
- Added SetOwnedCellsState() and EnsureCellMode() to re-stamp the owned footprint on Exiting/Waiting/Backing transitions
- Replaced ReleaseTailCellsByDistance/ReoccupyTailCellsByDistance with ReleaseTailCells(), releasing a cell only after the tail passes its far boundary
- Added PlayTailDots() firing the picture-reveal dot at cell centres on any forward advance; reversing never calls it
- Replaced ReleaseAllRemainingPathCells with ReleaseAllOwnedCells(), covering path and exit-lane cells
- Deleted DetectPhysicsBlocker() and CheckBlockerCollision(); cell claiming removes the need for the raycast backstop
- Deleted TryGetExitBlocker() and UpdateWaitState()
- CheckIfFullyExited() now finishes a serviceless arrow instead of moving forever
- AnimateIntro no longer writes _FillProgress; it calls UpdateLinePoints() so the body grows geometrically tail to head
- Head/tail/limb visibility toggles added to intro completion and FinishArrow

Arrow.cs — [MOD]
- Replaced _releasedCellCount/_releasedExitTrailCount with _claimHead, _releasedCount and _dotCount
- Added _cellMode (CellState) and derived _isWaiting from it so there is one source of truth
- Added _exitStep cached in RebuildWaypointsAndDistances
- IsHeadBlocked/IsHeadBlockedByStationary/ExitBlockerDistance now pass `this` as the ignore arrow
- Added tailRenderer SpriteRenderer field plus headAngleOffset, tailAngleOffset and tailSize
- Added handSprite and legSprite fields and the four limb SpriteRenderers built in code (_leftHand, _rightHand, _leftLeg, _rightLeg)
- Exposed _lineWidth and _arrowHeadSize as SerializeField so they act as prefab fallbacks
- Added GeckoConfig lazy accessor via ConfigService plus per-property accessors (HeadSize, BodyWidth, TailSize, limb, walk and crawl params) falling back to serialized values
- Added editor-only RefreshVisualFromConfig() in Update so GeckoConfigSO tweaks preview live on resting arrows in Play mode

GameplayConfigSO.cs — [MOD]
- Removed the dead arrowWaitGap field now that waiting is decided by cell claiming

----------------------------------------------------------------------

2. Arrow Visual (Gecko)

Arrow.Visual.cs — [MOD]
- Removed the _FillProgress shader property; the intro fill is geometric now
- Renamed SetAllLinePoints to PrepareBodyLineForIntro and switched the body LineRenderer to LineTextureMode.RepeatPerSegment so each cell shows exactly one body diamond
- UpdateLinePoints emits a vertex at every cell centre the body spans (path and exit lane) so exit-lane tiling stays uniform
- Added EnsureLineCacheCapacity() growing the line-point buffer when the swept body exceeds the path-length estimate
- Added ApplyBodyTiling() setting _MainTex_ST to BodyTilesPerCell for the GeckoBody and DefuseArrow materials
- SetMaterial no longer overwrites the head material so the head keeps its own GeckoSprite texture
- Added UpdateArrowTail() positioning and rotating the tail sprite at the body end
- Added SpriteAngle() aligning a sprite authored facing +Y to a travel direction
- Added SetTailVisible()
- Added SetupLimbs() and CreateLimb() building four limb SpriteRenderers once, sharing the tail material and sorting at order -1 under the body
- Added UpdateLimbs() and PositionLimbPair() riding each pair at a fixed arc distance behind the head with lateral splay, right limb mirrored across the body axis
- Added a walk cycle driven by _headDistance: hand and leg swings run pi out of phase, right foot swing negated so the pair stays mirrored
- Added ApplyLimbVisibility, SetLimbsVisible, ApplyBoundsToLimbs, ApplyLimbBounds, SetLimbsColor, ApplyLimbColor so limbs share the bounds mask and the blocked-flash tint
- Added ApplyCrawlOffset() applying a head-anchored lateral sine to rendered body points only, leaving cell claim, tiling and reveal timing untouched
- Added CrawlTangent() returning the derivative of the wavy centreline so head, tail and limbs lean into the weave
- Added TryGetCrawlParams() gating the crawl and computing wave number plus amplitude ramp
- SetLineColor now forces white; the incoming ColorId tint is deliberately dropped during the gecko visual test

ArrowHeadVisual.cs — [MOD]
- Replaced MeshFilter/MeshRenderer with a single SpriteRenderer so the gecko head PNG composites with alpha
- Setup() signature dropped the GameObject model parameter; the sprite is authored in the prefab
- Added Initialize() guards to SetColor and SetBoundsMask
- Null-guarded the SpriteRenderer in OnGetFromPool and OnReturnToPool
```
