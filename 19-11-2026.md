3. Ice Obstacle

IceObstacle.cs — [MOD]
- While frozen, the block body is drawn with an ice skin (iceSkin x iceTint) so its color is hidden; the arrow stays visible
- Ice shell mesh stretches along the block length (BlockVisual.LengthRatio), detecting the local axis since the mesh is rotated in the prefab
- Layer count stays upright like Hidden's "?"
- Tapping a frozen block shakes it and bumps the count; breaking the ice restores the color with a pop
- Hidden takes priority over Ice when a block has both

BlockVisual.cs — [MOD]
- Added iceSkin / iceTint fields, SetFrozen() and PlayThaw(); frozen body uses the ice skin while Hidden still wins over Ice
- Added LengthRatio (body length / cell size) used to stretch the ice shell
- Board count is hidden while the block is hidden or frozen (RefreshBoardCount)
- Skin slice is now picked through BlockColorConfig.SkinOf instead of the color name

----------------------------------------------------------------------

4. Lock and Key

KeyObstacle.cs — [NEW]
- Key as an obstacle on a block (plain, Hidden, Ice, Stack); never blocks the block's movement
- Sits upright in the block's top-right corner
- When its block leaves the board, claims the first closed Lock with the same Id and flies there in an arc; one key opens one lock, a spare key flies up and vanishes

LockElement.cs — [MOD]
- Lock is a standalone one-cell blocker with pose and Id; blocks that hit it stop and it plays a bump
- Lock leaves the board and the board recalculates only after the key lands, so no block passes through while the key is in flight
- Model scaled 1.4x to fill the blocked area

LockKeyColors.cs — [NEW]
- Separate Id color table per GDD: 0 yellow, 1 red, 2 green, 3 blue, 4+ yellow

KeyElement.cs — [DEL]
- Standalone key element removed; key is now KeyObstacle. No level used it

Block.cs — [MOD]
- Blocked move plays LockElement.PlayHitReaction when the hit target is a Lock
- Raises GameEvents.RaiseBlockRefused on no-slot and failed clicks, RaiseBlockBumped on blocked moves

BlockKey.prefab — [RENAMED from Key.prefab]
- Key model moved to the block-attached prefab

Lock.prefab — [MOD]
- Model scale set to 1.4
- Added LockElement fields hitPush, openPop, openDuration and keyTarget

ObstacleDatabase.asset / BoardElementDatabase.asset — [MOD]
- Registered BlockKey in the obstacle database, removed Key from the element database

GridPlaceholderBuilder.cs — [MOD]
- Loads BlockKey.prefab into the obstacle database instead of building a Key element
- Sample token K0 now means a block carrying Key Id 0, L0 a Lock with Id 0
